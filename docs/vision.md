# The Go Room 项目愿景与交接

记录日期：2026-10-25（历史愿景）

> 本文保留项目起步时的讨论，不代表当前待办。已确定采用 Vite + React + TypeScript 的纯前端架构、中国规则数子、白贴 7.5、全局同形禁止与简单电脑对手；视觉采用「墨与印」（此前为 B「棋谱编辑部」）。当前功能见[项目介绍](../README.md)与[详细状态](status.md)，已确认范围见[第一版设计](superpowers/specs/2026-11-01-v1-design.md)。

The Go Room 是独立的围棋学习与对弈项目，目录为仓库根目录。项目以 README 和愿景文档建立本地 Git 版本记录，尚无实现代码。项目名称后续可以调整。

## 项目目标

打造一个能够长期发展的高阶围棋学习与对弈应用，对零基础用户友好，同时保留深入学习和提高棋力的空间。

围棋知识与术语应使用容易理解的方式解释。

## 已讨论并认可的总体方向

- 独立开发围棋学习项目。
- 将学习、对弈和复盘结合起来，让用户在实际落子中理解规则。
- 长期目标可以高阶，开发从小而完整的体验开始。
- 使用安静、清晰、让人愿意专注下棋的体验作为设计方向；具体视觉方案尚未确定。

## 第一版建议范围

下面是上一轮对话提出的路线，尚未形成逐项确认的开发规格：

**几分钟互动教学 → 一盘有辅助提示的 9 路棋 → 一次看得懂的复盘。**

1. 互动教学：通过可操作的局面认识落子、棋块、气和提子。辅助标记应能帮助初学者看懂棋盘。
2. 引导对局：从 9 路棋盘开始；解释不合法落子的原因，逐步介绍劫、停一手和终局。
3. 简单复盘：能够回看步骤，了解关键变化。只有具备可靠分析依据时，才给出棋力评价或更优下法。

开发可先完成规则与本地双人操作，再接入电脑对手。对弈模式和第一版 AI 深度需在实施前决定。

## 长期发展候选

- 13 路与 19 路棋盘。
- 难度适合初学者且可逐渐提高的电脑对手。
- 棋谱保存、导入导出与复盘。
- 死活题，以及眼、连接、地盘、全局判断的逐步教学。
- 基于围棋引擎的局面分析和关键失误讲解。

联网对战、账号、排名、社交功能尚未列为确定需求。

## 规则与 AI 的实现原则

- 围棋规则应独立于界面实现，方便测试、复用和以后扩展。
- 开发前明确采用的规则体系、贴目、重复局面处理和终局计分方式；不同规则的细节不可混用。
- 覆盖提子、禁入点、劫、连续停一手、死子处理与计分等关键场景。
- 强棋力可考虑接入成熟围棋引擎，具体引擎、运行方式、授权与成本需要后续调研。
- 不将语言模型直接当作可靠的规则裁判或棋力引擎。教学解释应能对应实际局面，并与规则或分析结果核对。
- 面向初学者的解释优先讲清一步棋的目的，例如保护一块棋、连接棋子或争取地盘。不要只展示胜率数字。
