## 已检查

- 全量 201 个测试通过，生产构建与 lint 通过。
- 引擎正式落子与慢镜头共用 `inspectPlay`：一眼先提 14 颗黑子后白子有 4 气；两眼提不到黑子，白子无气而拒绝，恢复原盘面。
- 实际 Chromium 完整走完两例慢镜头与原因选择、三种空区归属、四次数子、贴目和胜方判断、连续停手、死子演示与确认数子。
- 正常教学终局：黑 28 活子 + 8 空点 = 36；白 27 活子 + 8 空点 = 35，再加 7.5，白胜 6.5。中央 10 个公共空点不计。

- 320、390、768、1024、1440 宽度无横向溢出；键盘可操作棋盘与输入框，手机触屏选空区成功。
- 回归原五关、八个生存场景、陪练预览与同回合重试，运行时无控制台警告或错误。
- 目视检查棋子尺寸、提子前后盘面、空点标记、计分明细和手机上下布局。

## 请项目负责人试用

1. 从章节的“规则慢镜头”进入，尝试用自己的话回答：为什么白棋周围都是黑棋，却不一定是禁入点？
2. 完成“围地与终局”四课，检查能否解释：空点如何归属、为什么不是吃子多就赢、贴目加给谁。
3. 终局课先让白棋继续下，再让双方停手；检查能否区分停一手、连续停手和死子确认。
4. 带着这些理解去下一盘陪练，记录仍不知道该怎么做的具体时刻。

这些固定例子用于解释规则。界面没有通用自动死活判定，也没有判断中盘领地或推荐最佳策略。流程与渲染已验证，学习效果需要初学者实际体验。
