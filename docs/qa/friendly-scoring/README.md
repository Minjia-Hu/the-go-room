# 陪练结束与数子验收

日期：2026-11-08。使用 `npm run dev` 临时启动本地服务，以 Chromium 实际操作桌面 1280 × 900 与手机 390 × 844 触屏页面，结束后关闭临时服务。

## 自动检查

- 全量 237 个测试通过（本轮新增 13 个），构建与 lint 通过。
- 随机候选排除未提子的自叫吃；提子后仅剩一气仍允许，原提子、救子、叫吃优先级不变。玩家停手不会自动触发电脑跟停。
- 约定追加两次停手，以及白棋已停时只追加黑棋停手，都由规则引擎重放核验。白棋回合不能提出数子；重复确认不会多加动作。
- 数子返回恢复盘面、同形历史、随机状态与原有重试机会，丢弃死子标记；自然连续停手也支持返回。
- 新棋谱保存并读回结束来源，旧 v1 棋谱不增加字段，拒绝损坏或与行棋顺序不符的约定标记。
- 严格模式下确认、取消、思考期间禁用入口、返回、最终保存；未确认试下不进入棋谱。只有电脑实际继续落子时显示停手后的提示。

## 浏览器检查

- 未确认试下后提出数子，试下被清除，正式手数不变；取消可继续落子。
- 与实际电脑下一回合，提出数子并标记死子；返回后棋盘、手数和重试机会恢复，死子标记清除。重试相同选择，实际电脑应手相同。
- 保存后刷新，仍保留双方同意数子的说明；逐手回看只在对应末尾停手显示“按约定”，普通历史不混入该说明。
- 陪练开启与关闭时，黑棋停手、白棋实际继续落子后均出现明确反馈。
- 键盘 Enter 可确认数子；手机触屏可提出、标记、返回和保存刷新，无横向溢出。已查看下列截图，棋盘、棋子、标记与按钮排版正常。
- 原五关、八个生存场景、试下切页清除、键盘试下与最近回合重试均回归通过。浏览器未出现页面错误或控制台警告。

## 保留的边界

电脑接受结束和死子标记是陪练约定，不是自动判断棋已下完。得分依赖玩家确认的死子标记；测试通过不能证明死活判断正确或教学效果达标。自动跟停、学习记录持久化、方向键和愿景文档整理不在本轮范围。
