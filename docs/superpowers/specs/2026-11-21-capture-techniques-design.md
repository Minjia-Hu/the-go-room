# 吃子技巧章节设计

记录日期：2026-11-21

## 背景

V2EX 反馈（<https://www.v2ex.com/t/1257558>）5 楼：课程进度太快，缺少征吃、枷吃、接不归等内容。

现有课程中，“保住自己的棋”只教防守（认危险、逃跑、连接、两只眼），学完直接进入围地与终局，没有任何教怎样吃对方棋子的内容。新手“跟电脑下一直被吃，不知道哪里下错”，与缺少这部分直接相关。打劫已在规则第 5 关讲过，不重复。

## 目标

新增一卷“吃掉对方的棋”，让学习者：

- 会从正确的方向叫吃；
- 认得双叫吃、征子、枷吃、接不归；
- 知道自己的棋被征时，什么情况下不该再逃。

## 范围与分段

全章五课，每课两题（一道引导题、一道检验题），共 10 个课程单元。另在“练”页新增分组“别被吃”。

**第一段（本次实施）：**

1. 追吃机制（题型、白棋应对策略、页面）。
2. 第 1 课：往哪边叫吃（含门吃、抱吃）。
3. 第 2 课：双叫吃。
4. 第 3 课：征子。
5. “别被吃”分组的两道征子题：路上没有接应 / 路上有接应。

第一段完成后课程单元从 29 个变为 35 个。

**第二段（第一段在浏览器中试用确认后另行实施）：**

- 第 4 课：枷吃。
- 第 5 课：接不归（需要额外的“如果白棋硬接”演示）。

**不做：** 倒扑、扑（留到以后）；修改陪练电脑对手；修改其他卷的内容。

## 章节位置

插在“保住自己的棋”之后，作为第叁卷。后续卷号顺延：围地与终局 → 肆，九路策略入门 → 伍，从看懂到自己下 → 陆，有提示的陪练 → 柒。

学习记录使用带前缀的稳定 ID（新章节为 `capture/<scene-id>`），不依赖卷号与数组位置，老用户的已有记录不受影响。

## 追吃题型

### 交互

- 学习者执黑。点棋盘直接落子，不需要“试下 → 确认”。多回合追吃每手都确认太慢；用“退回一手”弥补。
- 黑棋落子后，白棋由策略函数**现算**一手应对，不写死应对走法。学习者下任何合法的一手都会得到真实回应。
- 每次黑棋落子后依次判断：
  1. 任一目标白棋块被提走 → 成功（`done`）。
  2. 否则由白棋应对，之后：
     - 白棋提走了黑棋 → 失败：“白棋反过来吃掉了你的棋。”
     - 目标白棋块（以白棋应对后的整块计）有 3 口及以上的气 → 失败：“白棋逃出去了。”
     - 黑棋已用完本题的手数上限 → 失败：“手数用完了，白棋还没被吃掉。”
- 失败后棋盘停在失败局面，显示原因，提供“退回一手”和“重来这一题”。失败计入 `mistakes`。
- “退回一手”撤销上一对黑白落子，不计入错误；成功后不再提供。
- 非法落点沿用现有解释（禁入点、劫等），计入 `mistakes`，与现有练习一致。

### 白棋应对策略 `captureReply(state, targets)`

纯函数，放在课程代码中（例如 `src/app/lessons/captureRunner.ts`），不改 `src/ai/`。规则按顺序：

1. 若有与目标白棋块相邻、只剩一口气的黑棋块，提掉其中最大的一块（同样大取扫描顺序靠前者）。
2. 否则，对每个仍在盘上、气数最少的目标白棋块，逐个试下它的每一口气；选出试下后该棋块气数最多的点（同样多取扫描顺序靠前者）。若最多的气数至少为 2，就下这一点。
3. 否则（怎么走都只剩一口气，即已逃不掉），白棋停一手，并提示“白棋已经逃不掉了，提掉它。”

目标棋块用题目给出的若干坐标标识；每次判断时取包含这些原始白子的当前棋块。

### 题目数据 `CaptureScene`

放在 `src/content/capture.ts`：

```ts
interface CaptureScene {
  readonly id: string
  readonly lesson: number            // 1-5
  readonly title: string
  readonly guided: boolean
  readonly rows: readonly string[]   // 与现有题目相同的 9 路字符盘面，黑先
  readonly targets: readonly Point[] // 目标白棋块中各取一颗
  readonly maxMoves: number          // 黑棋手数上限
  readonly solution: readonly Point[] // 一条经策略验证能成功的黑棋落子序列，用于演示
  readonly wrongFirst: Point          // 典型错误的第一手，用于对照
  readonly contrastRows?: readonly string[] // 征子课：路上有接应的对照局面
  readonly intro: string
  readonly hints: readonly [string, string, string]
}
```

### 提示与对照

- 三级提示与现有生存课一致：第 1 级文字；第 2 级标出目标白棋块与它的气；第 3 级自动演示 `solution`（记为跟着演示完成）。
- 引导题完成后，“看看对照”折叠中提供：
  - “如果先从另一边叫吃”：从原图下 `wrongFirst`，按策略自动走到失败为止，逐手可看。
  - 征子课另有“如果路上有白子”：在 `contrastRows` 上自动走 `solution` 的前缀，直到失败，说明征子不成立时追的一方会怎样。

### 页面

复用生存课的分步布局（标题区步骤、棋盘旁最多一个主按钮、讲解与图例默认收起）。步骤标签：

- 进行中：“追吃中 · 已下 n 手 / 最多 m 手”，任务句由题目给出（例如“叫吃白棋，把它赶向边上”）。
- 失败：“这次没吃到”，主操作为“退回一手”。
- 完成：完成方式标签，与学习记录一致。

完成方式计算与 `survivalCompletion` 相同：演示 > 提示 > 引导 > 重试 > 独立。

## 各课内容（第一段）

每课两题，标题、局面由实施时设计，须满足下列要求并由测试验证。所有追吃题的目标白棋块在原图中最多 2 口气，否则“3 口气即逃出”的判定会在第一手就触发。

**第 1 课：往哪边叫吃。** 引导题：同一颗白子，从一边叫吃会被它逃向空处，从另一边叫吃把它赶向棋盘边或黑子（门吃、抱吃）。`wrongFirst` 必须是让白棋逃出去的方向。检验题：换位置、换方向。

**第 2 课：双叫吃。** 引导题：一手同时叫吃两块白棋，白棋只能救一块。`targets` 含两块，提走其中任一块即成功。检验题：换局面，并有一个看似可以叫吃、却只叫吃一块的干扰点作为 `wrongFirst`。

**第 3 课：征子。** 引导题：经典征子，一路叫吃到边上提掉，`maxMoves` 足够走完。`contrastRows` 为同一局面在征子路线上多一颗白子，追到那里时白棋连上、逃出。检验题：换方向的征子，`wrongFirst` 为从错误一侧叫吃（白棋逃出）。

## “别被吃”练习分组（第一段两题）

“练”页新增分组“别被吃”，学习者视角换成被追的一方（仍执黑）：自己的黑棋被叫吃，选择“继续逃”还是“在别处下”。

- 数据为两个选项，每个选项配一条**固定**的落子序列（白棋追、黑棋逃交替），由引擎逐手重放并校验合法（做法同策略课的固定变化）。这里只是演示双方都按最直接的方式走，不需要现算。
- 题 1：路上没有接应。“继续逃”的序列以整串黑棋被提走结束，正确答案是“在别处下”。
- 题 2：同样的形状，但路上有黑子接应。“继续逃”的序列以黑棋连上、逃出结束，正确答案是“继续逃”。
- 交互沿用“先后判断”：先选择、看序列逐手重放、再选原因才算完成。
- 记录 ID 为 `practice/<scene-id>`，不进入课程计数。

## 测试要求

- `captureReply` 单元测试：提子优先；选择气最多的逃跑点；逃不掉时停一手；同分取扫描顺序靠前。
- 每道追吃题：
  - 按 `solution` 落子、白棋按策略应对，在 `maxMoves` 内提走目标；
  - 从 `wrongFirst` 开始，按策略应对，最终判为失败；
  - `contrastRows`（如有）上走 `solution`，最终判为失败。
- 每道“别被吃”题：两条序列逐手合法，结局分别符合上面的描述。
- 页面测试：失败后可退回一手；成功后无“退回一手”；最多一个实心主按钮。
- 学习记录：新单元出现在 `LEARNING_UNITS` 中且位于生存课之后；总数 35；旧记录不受影响；“继续学习”能打开新章节。
- `npm test`、`npm run build`、`npm run lint` 全部通过。
