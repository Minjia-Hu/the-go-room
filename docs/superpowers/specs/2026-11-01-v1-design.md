# The Go Room 第一版设计

记录日期:2026-11-01
状态:已与项目负责人逐段确认,作为第一版实施计划的依据。

## 1. 目标与范围

第一版交付一条完整的初学者路径:

**5 关互动教学 → 一盘与简单电脑对手的 9 路引导对局 → 一次带规则事件标注的复盘。**

已确定的决策:

| 事项 | 决定 |
|------|------|
| 运行平台 | 浏览器网页,纯前端,无后端,部署为静态站 |
| 技术栈 | Vite + React + TypeScript,Vitest 测试,SVG 棋盘 |
| 对局对手 | 自写的启发式简单电脑对手,不接外部引擎 |
| 规则体系 | 中国规则,数子法,黑先白贴 7.5 目,全局同形禁止,禁止自杀 |
| 教学形态 | 5 个固定关卡,内容为数据文件 |
| 复盘形态 | 逐步回放,标注规则层面可确定的事件,不做棋力评价 |
| 存储 | localStorage 保存最近若干盘棋谱 |

明确不在第一版内:13/19 路界面、外部引擎分析、SGF 导入导出、死活题、联网对战、账号。引擎本身接受任意棋盘尺寸,但界面只提供 9 路。

## 2. 整体结构

单个 Vite 项目,四层,依赖只能向下:

```
src/
  engine/   围棋规则,纯函数,零依赖
  ai/       简单电脑对手,只依赖 engine
  content/  教学关卡数据,只依赖 engine 的类型
  app/      React 界面:棋盘、教学、对局、复盘
```

- `engine` 对外暴露:创建棋局、尝试落子(返回新状态或拒绝原因)、停一手、判断是否终局、标记死子、数子计分。状态为不可变数据对象。
- `ai` 暴露一个函数:输入棋局状态,输出落点或停一手。
- `content` 为关卡定义:初始局面、任务说明、正确落点、错误提示文案。
- `app` 是唯一接触 DOM 的层,把 engine 状态渲染为 SVG,把用户点击转为 engine 调用。

设计原因:规则独立于界面是愿景中的硬要求;日后更换棋盘尺寸或替换 ai 为外部引擎时只改一层。

## 3. 规则引擎口径

- **棋盘**:尺寸为参数,第一版默认 9。
- **落子合法性**,按顺序检查:
  1. 目标点必须为空。
  2. 落子后先移除无气的对方棋块。
  3. 若此时己方该块仍无气,为禁入点(禁止自杀),拒绝。
  4. 若落子后的盘面与本局任何历史盘面相同,拒绝(全局同形禁止,覆盖普通劫)。
- **停一手**:任何时候可停。连续两次停一手进入终局阶段。
- **终局与死子**:终局阶段双方可点击标记死子,标记按整块切换。确认后移除死子再数子。电脑对手第一版默认同意用户的标记。
- **数子**:每方得分 = 盘上活子数 + 只被己方包围的空点数。双方都接触的空点不计。
- **贴目**:白 +7.5。结果 = 黑得分 − 白得分 − 7.5,正为黑胜。贴目值可配置,第一版界面不暴露。
- **拒绝原因**为枚举:`occupied`、`suicide`、`repeated-position`。界面负责翻译为初学者能理解的文字。
- **每步记录**的事件:提了几子及位置、是否形成劫、是否停一手,供复盘使用。

## 4. 简单电脑对手

固定优先级选点,全部基于 engine 提供的合法性与气数查询:

1. 若有能提掉对方棋块的点,选其中提子最多的。
2. 若己方有只剩一口气的块且可通过落子增气逃出,选该点。
3. 若能把对方某块逼到一口气,选该点。
4. 否则从剩余合法点中随机选,排除会填掉己方眼位的点(眼位定义:该空点四邻全为己方子,且对角线己方占多数)。
5. 无合适点时停一手。

随机选择使用可传入的种子,便于测试复现。棋力刻意弱,目标是让初学者能完整下完并有机会赢。

## 5. 教学关卡

5 关,每关包含:初始局面、任务说明、正确落点集合、错误落子时的针对性提示文案。全部为数据,不含逻辑。

1. **落子**:在任意空点下一子,认识交叉点。
2. **气**:点出被标出的一块棋的所有气。
3. **提子**:下一子把对方一块棋提掉。
4. **禁入点**:局面里有一个禁入点和一个合法点,选合法的那个;选错时解释为什么不能下。
5. **劫**:提劫后立刻回提会被拒绝,用户体验到"不能马上回提",关卡提示引导其在别处落子。

错误落子只显示关卡里预写的提示,不生成文案。全部通过后进入引导对局。终局数子不单独设关卡,放到对局终局时现场讲解。

## 6. 引导对局

- 用户执黑,电脑执白,9 路。
- 常驻辅助标记:当前落子高亮;刚被提掉的位置短暂标记;只剩一口气的块可选显示。
- 落子被拒绝时显示一句原因。
- 首次说明,每项只出现一次:第一次遇到劫、第一次停一手、进入终局。
- 终局流程:标记死子 → 确认 → 显示数子结果,并逐区域高亮各方的子与空。

## 7. 复盘

- 对局结束自动进入。提供上一步、下一步、跳到开头、跳到结尾。
- 每一步旁列出规则事件:提了几子、被提几子、劫、停一手。
- 最后一步显示数子结果。不做好坏评价,不给更优下法。
- 棋谱存 localStorage,可回看最近几盘。

## 8. 界面基线

- 视觉风格尚未定稿,第一版用克制基线:单色浅底、木色棋盘、黑白子、少量强调色做标记。详细视觉方案另行讨论,不阻塞第一版。
- 三个页面:教学、对局、复盘,顶部简单导航。响应式,手机竖屏可用。
- 棋盘与所有辅助标记均为 SVG 层。

## 9. 错误处理

- engine 不向界面抛异常;拒绝落子一律通过返回值表达。
- localStorage 读取失败或格式不符时按"没有历史棋谱"处理,不影响下棋。
- 电脑对手返回非法点时,界面兜底让其停一手,并输出控制台日志。

## 10. 测试

- **engine**:Vitest,每条规则一组场景用例:提子、禁入点、普通劫、超级劫、连续停一手、死子移除、数子与贴目。
- **ai**:给定局面断言优先提子、优先救气、不填眼;同一种子结果可复现。
- **content**:一个测试遍历所有关卡,验证正确落点在 engine 中确实合法且达成任务。
- **app**:少量冒烟测试,保证三个页面能渲染、落子能触发 engine。

## 11. 验收标准

1. 一个没接触过围棋的人能在教学里走完 5 关,每关错误时得到对应提示。
2. 能和电脑完整下完一盘 9 路棋,过程中至少遇到一次被拒绝落子、停一手和终局数子。
3. 终局结果与手工按中国规则数出的结果一致。
4. 复盘能逐步回看,并看到每步的提子、劫、停一手标注。
5. engine 测试全部通过,`npm run build` 产出可直接部署的静态站。
