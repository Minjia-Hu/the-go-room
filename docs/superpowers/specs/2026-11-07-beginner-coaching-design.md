# The Go Room 生存练习与新手陪练设计

日期：2026-11-07

状态：项目负责人已于 2026-11-07 确认本方案，下一步编写具体实施计划。功能尚未开始实现。

依据：[第一版设计](2026-11-01-v1-design.md)。本方案是下一阶段的范围增补，不改写已确认的第一版设计。

## 1. 要解决的问题与学习目标

目前用户学完五关，知道可以怎样落子，却仍不知道该关心哪块棋、为什么要救、怎样救。电脑会抓住这些遗漏提子，现有提示和复盘只能描述结果。

本次增加四课生存练习，并把默认对局变成可试下、可解释、可重试的新手陪练。核心体验是：**发现危险 → 自己试一手 → 看见原因与后果 → 再作决定。**

完成后希望零基础用户能够：

1. 找到一块黑棋及其剩余的气，解释“为什么对手下一手可能提掉它”。
2. 在简单局面中通过向外延伸、连接或提掉包围的棋来暂时解除威胁。
3. 区分“这一手暂时解除危险”和“这块棋已经有两只真正的眼”。
4. 在真实对局被吃后，指出对手占住的最后一口气，并重试之前的选择。

这次的验收不要求赢电脑，也不承诺学完就懂布局、围地和复杂死活。保留一句目标说明：“最后比较活着的棋子和围住的空点，吃子只是办法之一。”围地和终局专项教学留待下一阶段。

## 2. 学习入口与范围

教学页分成“认识规则”和“保住自己的棋”两个章节。保留原五关及其独立重练入口；第五关结束后的主按钮改为“练习保住自己的棋”，同时提供“直接开始陪练”。已有用户可以直接进入新章节。

新增四课，每课包含一个有引导的例题和一个换位置、减少提示的检验题，共八个固定场景。棋盘仍为 9 路，主要棋形集中在局部；不引入另一套棋盘尺寸。每课只突出一个概念，用户随时可以重来、回看、跳过或进入对局。

新手陪练默认开启，不会在完成一盘后自动撤掉。用户可关闭陪练回到现有直接落子的方式，之后也可重新开启。这里的“第一盘”指首次对局的体验，不依赖历史棋谱数量判断身份，也不强迫做完课程才能下棋。

本次不增加外部围棋引擎、语言模型调用、账号、后端、胜率、棋力评分、自动死活判定或战略最佳点。沿用现有电脑优先级；帮助来自可理解的提示和重试。

## 3. 四课生存练习

| 课程 | 用户先做什么 | 看见什么、为什么 | 检验题 |
| --- | --- | --- | --- |
| 1 认出哪块棋危险 | 在两块黑棋中选出只剩一口气的一块，再点出最后的气 | 圈出整块棋；演示白棋占住最后的空点后整块消失。“它们连在一起，共用这一口气。”此时再介绍术语“叫吃” | 换一个方向和棋块大小，不预先圈答案；自己找危险棋块和最后一口气 |
| 2 给自己的棋找出路 | 在同一个例题起点分别试向外延伸、提掉包围的白棋，两条分支都可解围 | 每次从同一起点对照：延伸让整块接触更多空点；提掉白棋会腾出新的气。两条分支的气都实际标出 | 使用另一个未演示局面：向外延伸仍只有 1 口气，提掉白棋才能解除直接威胁；允许逐级求助 |
| 3 把分开的棋连起来 | 先区分直线相邻和斜着相邻，再补上两块黑棋之间的缺口 | 两块合为一块，原来的危险棋借用相连棋块的气；共享空点只数一次。“能互相帮助”由本题实际气数和后续变化说明 | 换成竖向连接，并提供一个看似靠近、实际只斜着接触的干扰点 |
| 4 两个小空点为什么能保命 | 在预设的完整黑棋块中分别尝试让白棋进入 A、B 两个内部空点 | 分别试下，每次回到原图；任一处白棋都无气，又不能提走仍有另一口气的黑棋，因此被拒绝。对比仅剩一个内部空点且没有外气的局面，白棋能提掉整块黑棋 | 在另一个简单棋形中选出两只分开的真眼，并选择原因：“白棋一次只能填一个，另一个还在” |

第四课首次用白棋操作时明确标注：“现在暂时替白棋试一下，看看它为什么下不进去。”进入陪练后仍固定由用户执黑。

“眼”第一次出现时解释为“被自己的棋围住、留在里面的空处”。本课只使用同一完整棋块围住的两个独立单点真眼。不能把两个普通空点、一个连通的大空洞或假眼当作两个真眼，也不教“没有两眼就一定死”。自动识别任意局面的眼不属于本次功能。

### 3.1 每题的讲解方式

一屏先给一句任务，不先展示整段理论。各题共用“观察、尝试、对照、解释、迁移”五个阶段，具体操作随题型变化；找气题用选择，眼的题用白棋试入。以救子题为例：

1. **观察：** “先点一下你觉得有危险的黑棋。”
2. **尝试：** 用户选点，出现试下状态，正式练习起点仍保留。
3. **对照：** 用按钮切换“下之前 / 下之后 / 白棋接着下”；演示步由用户控制，不自动闪过。
4. **解释：** “原来只有 1 口气；向外接了一颗后，这块棋共有 3 口气。白棋一次只能占一处，不能下一手直接提掉整块。”实际数字由题目盘面核实。
5. **迁移：** 完成换位置的检验题，再进入下一课。

点错不扣分，也不直接只显示“错误”。例如：“这个点斜着挨着黑棋，不算气。找上下左右紧挨着的空点。”允许看见错误落点的后果，再回到题目起点试一次。

求助依次是“提醒我看哪里”→“标出相关棋块和气”→“演示一种做法”，后一级由用户主动点开。例题可默认提供第一层；检验题不预先显示正确点。使用演示也可继续，但完成反馈写“跟着演示完成”，不当作独立掌握。

### 3.2 一段具体的新手体验

第一课的后果演示使用下面的局部形状，并在结尾预告“下一课练习怎样找出路”。它位于 9 路棋盘中央，周围未画出的点为空。● 是黑棋，○ 是白棋，A 是待选空点。第二课另用延伸与提子都能解围的棋形，不沿用此图。

```text
· · ○ · ·
· ○ ● ○ ·
· · A · ·
· · · · ·
```

先不标出 A，问“这颗黑棋还有哪里能呼吸？”用户找到下方空点后标 A，并解释“上、左、右都被白棋占住，只剩这里”。

随后提供两种对照：

- **去远处下一手：** 演示白棋下在 A，黑棋被提走。文案：“你这一步没有增加这颗黑棋的气。白棋占住最后的 A，它就没有气了。”
- **黑棋下在 A：** 原黑棋和新黑棋相连，整块共有 3 口气，全部标出。文案：“新棋子把这块棋接向了空处，左右和下方都有气。眼前的危险暂时解除了。”

这样用户学到的是因果，而不只是记住“A 是答案”。检验题换成边上局面，不能沿用中央局面的气数。

## 4. 新手陪练的一回合

### 4.1 落子前先知道看什么

棋盘旁或手机棋盘下方常驻一张简短的陪练卡。优先显示当前黑棋的直接提子危险；只有一张主卡，其余危险可逐个切换查看。卡片所说的棋块和空点要在棋盘上对应标出。

典型文案：

> 先看看这 3 颗黑棋。它们只剩 A 这一口气；如果白棋下一手能下在 A，就能把整块提走。你可以先试试给它们找出路。

“白棋能下在 A”必须经过合法性验证。只有一口气但受劫或禁入点限制时，应写“只剩 1 口气，但白棋当前不能在 A 直接提走它”，不能错误报警。

点已有棋子用于查看该块及其气，不视为落子。卡片注明“点空点试下，点棋子查看气”。这种交互仅用于陪练；普通模式保留原有已占点提示。

### 4.2 先试下，再确认

陪练中的所有合法落子都先进入预览，适用于鼠标、触屏和键盘，不依赖悬停。棋盘明确标注“试下中，尚未落子”，新子用虚线外框；如会提子，预览显示提子后的盘面并可切换回原盘面。

提供“下在这里”和“重新选点”；点击其他空点也可替换试下位置。预览只展示下一次落子的直接后果，电脑此时不应手、正式手数和历史都不变化。

| 当前情况 | 展示的解释与选择 |
| --- | --- |
| 解除一块棋的眼前危险 | “这一步后，圈起来的黑棋从 1 口气变成 3 口，白棋下一手不能直接提走它。” |
| 新落子形成可立即被提的棋块 | “这一步合法，但这块黑棋将只剩 A 一口气。白棋接着下 A 就能提走它。”可以“看白棋怎样提”或重新选点 |
| 去别处落子，原有危险仍在 | “你选了另一处；左侧这块黑棋仍能被白棋下一手提走。”允许确认，不强制救棋 |
| 同时救一块、留下另一块危险 | 主文案先说明剩余危险，再说明已改善的棋块；不能只报好消息 |
| 两块黑棋连接起来 | “这两块现在连成一块，共有 N 口气。”仅当实际解除威胁时再补充“暂时解除危险” |
| 没有直接战术变化 | “这一步合法。落子所在棋块有 N 口气；目前未发现白棋下一手可直接提走的黑棋。”保留“这不代表以后一定安全”的简短说明 |
| 非法落子 | 解释占点、自杀或重复盘面等实际原因，正式盘面不变，不提供强行确认 |

“看白棋怎样提”在独立的演示盘面中展示一手合法提子，标签写“白棋可能这样应对”；不能声称电脑必然选择这一手。关闭演示返回同一个待确认落点。

### 4.3 我还是不知道下哪里

提供“给我一点提示”，先给观察方向，再由“看一个可尝试的点”显示一个候选和理由。

- 有可被直接提走的黑棋：寻找合法的解围候选，包括向外延伸、连接、提掉对手。展示前验证原目标棋子仍在，且白棋下一手无法直接提掉它们；同时揭示该走法留下的其他黑棋危险。
- 有多个候选：稳定选择一种并解释，不称“最佳”；不自动帮用户落子。
- 找不到能立即解围的候选：写“暂时没有找到能用一手解除这块棋直接提子危险的走法。你仍可试下看看”，不判死，不重复给出无法救出的伸出点。
- 没有紧急危险：先提示“看看自己的棋能否互相照应；点棋子可查看气，再试一个附近空点”。候选优先选能连接两块己棋的点，其次选邻接己棋并使连接后的气数增加的点；候选均排除让黑棋可被下一手直接提走的情况，不保证战略价值。文案说明练习目的，例如“试着观察这两块棋连起来后，怎样共享气”，不称其为当前最该下的点。
- 空盘第一手：给一个靠近角部的示例点，例如距上、左边各第三条线的交叉点。“可以从这里开始尝试，借棋盘的边帮助围出空间。这只是起点示例，不是唯一正确答案。”
- 没有上述候选：坦白显示“这次没有明确的建议点。你可以选一个空点，先看看试下结果”，不把随机落点包装成有依据的建议，也不因此自动推荐停一手。

候选连接与增气只是练习方向。系统不能推导“气越多，这步越好”或“每步都必须粘在一起”。

### 4.4 白棋下完，解释变化

保留现有 AI，确认黑棋落子后再启动电脑回合。白棋下完优先说明：提走了哪些黑棋；其次是使哪些黑棋变得可直接被提；再次是白棋自己解除的直接危险；无这些事件则仅陈述落点和轮到用户。

解释来自前后盘面的可验证变化，不猜测电脑意图。例如：“白棋占住 A，使这块黑棋只剩 B 一口气”，而不是“白棋正在发动精妙进攻”。

发生提子时保留被提位置和解释，提供“被吃前 / 被吃后”对照，前图圈出整块黑棋和被占住的最后一口气，后图标出白棋落点与被提位置。对照只用于查看，不改正式状态。提示保留到用户点“继续下”或“退回这一回合重试”。非提子事件不要求每回合点“知道了”，用户下一次试下即更新卡片。已有规则说明保留可展开入口，避免同时堆满多张卡片。

### 4.5 被吃后重试

陪练提供“退回这一回合重试”：撤销用户最近一次已确认的落子或停一手，以及其后的电脑应手，回到那次用户选择之前。只开放最近一回合，不增加任意历史编辑。

同时恢复盘面、轮次、连续停一手次数、同形历史、规则提示状态和该回合前的电脑随机状态，清除预览及旧提示。做出同样选择时，电脑可给出同样应手，便于对照学习。

电脑思考期间不开放重试；进入死子标记后、确认数子前仍可退回最近一回合；一旦确认数子并保存，使用现有复盘，不再改写该棋谱。没有可撤销回合时按钮禁用。

停一手也先解释并确认：“这一回合不落子；现有危险不会因此消失。”若白棋上一手已停，再说明“确认后进入死子标记”。演示与重试不是正式棋谱动作，最终只保存实际保留的行棋序列。

## 5. 显示与状态约定

- 继续使用木色 SVG 棋盘。圈出目标棋块，空心小圈表示它的气，A/B 字母对应讲解中的点；危险再加感叹号或文字，不能只依赖红绿颜色。
- 不同时标出所有棋块的所有气。默认展示当前讲解对象，其余通过点击查看；主卡提示还有几块危险棋。标记必须避开最后一手高亮，不盖住棋盘线。
- 手机竖屏让棋盘、主解释和确认按钮相邻；较长解释折叠。按钮和字母不能依赖悬停才能理解。
- 预览时换页或切换陪练开关，丢弃未确认选择；正式对局保留。确认后的电脑回合沿用切页取消计时器、返回后继续的规则。
- 课程内按“继续”才切换演示步骤；切到其他页面可保留当前课的内存进度。刷新后课程回到章节入口，进行中的对局仍不恢复，并在入口简短说明这一点。
- 陪练开关单独存入 localStorage，默认开启；读写失败或值损坏时仍可下棋，并以默认值开启。已完成棋谱继续沿用最近 10 盘格式。

## 6. 实现边界与解释可靠性

规则引擎继续只负责规则。新增讲解层使用 engine 的公开入口进行试下、查棋块和数气。课程盘面、步骤、提示及解释仍是内容数据；界面负责交互。下表用于后续拆实施计划，本次不实现代码。

| 部分 | 拟调整 |
| --- | --- |
| `src/content/` | 增加四课八场景数据；扩展选择棋块、原因选择、固定对照演示等步骤类型 |
| `src/app/lessons/` | 增加章节入口、逐级提示、独立演示状态和检验题反馈；保留原五关行为 |
| `src/app/coaching/`（新增） | 纯函数生成危险对象、前后气数、合法威胁与候选落点；结构化事实配固定中文模板 |
| `src/app/play/` | 接入试下确认、提子解释、最近一回合恢复与可恢复的随机状态 |
| `src/app/board/` | 增加目标棋块、气、A/B 点、试下与演示的清晰标记 |
| `src/app/App.tsx` | 管理陪练偏好、跨页保留的练习进度与对局相关状态 |

关键判定口径：

1. “可下一手提走”必须通过引擎验证对手落子合法，且提子记录确实包含目标棋块。具体黑棋试下后的检查直接使用引擎返回的新状态，此时轮到白棋；不能仅凭气数为 1 就下结论。
2. 黑棋选择前的威胁提示使用独立分析副本：盘面、阶段、历史和全局同形键全部保留，仅将 `toPlay` 设为白棋，检查其能否直接提子。不调用停一手，不写入正式状态，也不触发连续停一手终局；界面表述为“不处理这一处时的潜在威胁”。用户选定具体黑棋落点后，必须以真实试下的新状态重算；旧提示不是对所有黑棋选择的预测。
3. 对每块危险棋块分别计算，连接后的同一棋块去重；气数按空点去重。评估救子时追踪原目标棋子的存续，不以新落子的存活代替整块获救。
4. “白棋下一手不能直接提掉”只说明一手范围；不输出“无敌”“必胜”“已经活了”等更强结论。两眼的确定说明只用于经过核验的固定课程棋形。
5. 现有 AI 的 `isOwnEye` 是选点启发规则，不能直接作为教学中的真眼判据，也不能用于自动标死子。
6. 教学准备盘面不写入正式对局棋谱；无需为本次功能给 `GameState` 增加初始盘面。陪练仍从空棋盘开始。
7. 落子前后的“这块棋有 N 口气”等动态内容由计算结果填入模板；固定教学文案中的数字须与引擎核验一致。无可靠结论时展示事实或明确没有建议。

## 7. 验收方式

### 7.1 新手实际验收

由项目负责人以零基础视角试用，每一项都可指出具体棋块或空点，不以点击过关代替理解：

1. 在未见过的简单棋形中指出危险黑棋和最后一口气，并说出白棋下一手怎样提。
2. 在救子题中解释气如何变化，知道“暂时救出”不等于以后不会被吃。
3. 说明斜着靠近与真正连接的差别，并能指出连接后共用的气。
4. 对固定两眼棋形解释“白棋填一处时为什么仍提不走黑棋”，不只背诵“两眼活棋”。
5. 一盘陪练中主动试下至少一次，能根据提示改变一次选择；用可复现局面体验一次提子解释和回合重试。
6. 空盘或没有直接威胁时，能使用提示找到一个可试的方向；若仍只觉得“随便点”，这一项不通过，需要调整讲解。

不以获胜、少被吃几颗或读完说明作为唯一成功标准。若负责人仍无法说明为什么这样下，优先修订例题与文案，再增加功能。

### 7.2 开发验收

- 固定课程全部经引擎核验：正确与典型错误分支、每一步演示、气数、整块提子及两眼中的合法/非法尝试；不是只检查数据格式。
- 提示覆盖：自叫吃、忽略原有危险、提子解围、多块同时危险、连接共享气、合法性受同形限制、未找到解围候选，以及“看似多气但不能推出长期安全”。
- 交互覆盖：预览不改正式历史、不触发 AI；确认只落一次；取消、切页及切换模式清理预览；错误提示对应当前盘面。
- 重试覆盖：普通回合、双方停一手后、提子回合及劫历史恢复；恢复随机状态，同样选择得到同样应手；确认保存后不可改写。
- 现有教学、普通对局、终局数子、复盘和存储失败处理继续可用；运行 `npm test`、`npm run build`、`npm run lint`。
- 用 `npm run dev` 在真实浏览器检查桌面与手机竖屏。逐步操作八个场景和陪练，目视检查棋盘、所有新增标记和按钮，不能只依赖 DOM 测试。

## 8. 已确认的产品选择

项目负责人确认按本方案推进，并明确接受陪练默认开启、每手先试下再确认、允许退回最近一回合重试：

1. 四课、八个固定场景；先练认险、救子、连接，再认识两只眼。
2. 陪练默认开启，每手先试下再确认；允许关闭，完成第一盘后仍可继续使用。
3. 对局提供逐级提示和最近一回合重试，电脑策略保持现有优先级。
4. 提示只解释经过验证的局部后果；围地、完整布局教学及自动死活留待后续。
