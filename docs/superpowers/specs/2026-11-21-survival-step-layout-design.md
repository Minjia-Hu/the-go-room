# 生存课分步布局设计

记录日期：2026-11-21

## 背景

项目在 V2EX 发帖后收到三条实质反馈（<https://www.v2ex.com/t/1257558>）：

- 1 楼：某一课的界面看不出应该点击的顺序，也看不出点哪里去下一课。
- 2 楼：第一课文案“这 1 颗黑棋连在一起，共用 A 这一口气”不通，只有一颗棋。
- 5 楼：信息密度太高，都集中在右侧，不知道如何操作，建议分步骤、精简界面；另外课程进度太快，缺少征吃、枷吃、接不归等内容。

三件事分开处理：

1. 2 楼的文案问题已在分支 `codex/single-stone-wording` 修复，不属于本设计。
2. 1 楼与 5 楼前半是同一个问题，由本设计解决。
3. 5 楼后半（吃子技巧章节）另行立项。

## 目标

学习者在“保住自己的棋”八个场景的任何时刻，都能一眼看出：

- 现在是第几步、共几步；
- 这一步要做什么；
- 做完以后点哪里继续。

## 范围

只改生存课八个场景使用的通用页面 `src/app/lessons/SurvivalPage.tsx`。练习页复用该组件的专项题自动得到新布局。

不做：

- 规则、终局、策略、整盘讲解、独立练习等课型的布局；
- 把 `GuidedDangerPage` 并回通用页（它继续处理 `danger-guided`，并作为视觉样板）；
- 新课程内容；
- 删除任何现有功能或文案；
- 改动 `survivalRunner` 状态机、完成等级或学习记录。

## 设计

### 步骤表

新增纯函数 `survivalSteps(run: SurvivalRun)`，放在 `src/app/lessons/survivalSteps.ts`。它只读取现有状态，返回：

```ts
interface SurvivalStep {
  readonly current: number   // 从 1 开始；完成后等于 total
  readonly total: number
  readonly label: string     // 步骤名，如“找棋”
  readonly task: string      // 一句任务
  readonly progress?: string // 可选，如“已比较 1 / 2 种”
  readonly done: boolean
}
```

各课型的步骤：

| 课型 `kind` | 步骤 | 判定依据 |
|---|---|---|
| `danger` | ① 找棋 → ② 找气 | `stage` 为 `group` / `liberty` |
| `escape`、`connect` | ① 选点试下 → ② 看后果，再确认 | `stage` 为 `move`；`preview?.ok` 为真时是第 ② 步 |
| `eyes` | ① 试第一个眼 → ② 试第二个眼 → ③ 说出原因 | `stage` 为 `eyes` 时按 `selected.length` 区分；`reason` 是第 ③ 步 |

补充规则：

- `escape` 引导题要求比较所有示例救法。确认一种后回到第 ① 步，`progress` 为“已比较 n / m 种”，其中 n 为 `solved.length`，m 为 `scene.examples.length`。
- `stage` 为 `done` 时 `done` 为真，`label` 与学习记录的完成方式一致（取自 `COMPLETION_LABELS`）：`assisted` 为真是“跟着演示完成”；否则提示级数超过起始值（引导题 1、检验题 0）是“借助提示完成”；否则引导题是“跟着引导完成”；否则 `mistakes > 0` 是“重试后完成”，再否则是“独立完成”。借助演示或提示完成时，`task` 保留现有建议“可以重来一次，自己找答案 / 不看提示试试”。
- 引导题 `escape` 中已确认过的试下点不再算第 ② 步，也不再显示“确认这一步”。
- 任务句沿用 `SurvivalPage` 现有 `goals` 的措辞，按步骤拆分。单颗棋的场景不使用“整块”“连在一起”等措辞，与 `codex/single-stone-wording` 的修复保持一致。

### 页面槽位

`BoardLayout` 的四个槽位不变，内容重新分配。

**标题区 `heading`**

- 课程位置（现有 eyebrow）；
- 标题；
- 步骤标签，如“第 1 步 / 共 2 步 · 找棋”；完成后显示完成方式；
- 一句任务（完成后只在借助演示或提示时显示重来建议）；
- `progress` 存在时紧跟步骤标签显示。

**主操作区 `primary`**，任何时刻最多一个实心主按钮（回答原因时没有，只有两个选项）：

- 反馈文字。尚未有任何反馈时，在此位置显示场景引言 `scene.intro`；出现第一条反馈后由反馈替换。
- 试下后（`preview.ok`）：主按钮“确认这一步”；其下一行次要按钮“下之前 / 下之后 / 看白棋怎样提 / 重新选点”，出现条件与现在相同。
- `stage` 为 `reason`：两个原因选项，使用次要按钮样式。
- 未完成时：一个固定位置的提示文字链接，文案沿用现有三级提示。
- 完成后：见下节。

**折叠区 `detail`**，一个默认收起的 `<details>`，标题“讲解与图例”，内含：

- 场景引言（始终保留一份）；
- 棋盘图例；
- 目标棋块统计（出现条件与现在相同）；
- “分步看：为什么不算自杀？”（仅 `eyes`）。

### 完成状态

`stage` 为 `done` 时，主操作区自上而下：

1. 总结反馈（现有完成文案）。
2. 唯一的主按钮，文案写明去向：
   - 引导题：“换个局面，自己试试 →”；
   - 检验题：“下一课 · 〈下一课标题〉 →”，标题取下一个场景的 `title`；
   - 最后一题：主按钮“学习围地与终局 →”，旁边次要按钮“开始我的陪练”；
   - 调用方传入 `nextLabel` 时以它为准（练习页依赖这一点）。
3. “看看对照”折叠，默认收起：
   - `danger`：“如果去远处下 / 如果接向空处”；
   - 有 `contrastRows` 的 `eyes`：“只剩一个眼时 / 白棋填最后一气 / 回到两眼原图”。`stage` 为 `reason` 时这组对照也可用，同样放在折叠内。
4. “重来这一题”文字链接。

### 页面工具栏

- 顶部“返回章节”“直接开始陪练”位置与样式不变。
- 生存课页面底部的“回看上一题”“先跳过这一题”保留，改为灰色小字，不使用朱红。只作用于生存课页面的工具栏，其他课型不变。

### 手机

`board-flow` 现有顺序已是“任务 → 棋盘 → 主操作 → 详情”，不新增布局。折叠后首屏更短。步骤标签字号不小于 12 px，与现有手机规则一致。

## 测试

- 新增 `survivalSteps.test.ts`：四种课型的每个步骤、`escape` 引导题的“已比较 n / m 种”、各种完成方式。
- 新增或扩充 `SurvivalPage` 组件测试：
  - 每个阶段最多一个实心主按钮；
  - “讲解与图例”与“看看对照”默认收起；
  - 首次操作前显示引言，操作后显示反馈；
  - 完成后主按钮文案带去向，`nextLabel` 优先。
- 调整现有测试：直接查询已折叠内容的用例，先展开再查询。
- `survivalRunner` 的测试不改。

## 验收

- `npm test`、`npm run build`、`npm run lint` 全部通过。
- 在浏览器中走完八个场景，桌面与 375 px 宽各一次，确认每一步都能看出顺序与去向。
- 练习页的认危险专项题与四道生存检验题可正常完成，完成记录不变。
