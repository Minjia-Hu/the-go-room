# 陪练结束与数子体验

按用户确认的范围实现，保留中国规则引擎与 B 版界面。重点是让玩家能结束对局，同时明确电脑的能力边界。

## 范围与实现

- 随机选点时，模拟落子并排除“未提子且落下的棋块仅剩一口气”的候选。提子、救子、叫吃的优先级和逻辑不变；不判断对方地盘或通用死活。没有符合当前策略的候选点时停手，不做自动跟停。
- 轮到黑棋时可“提出结束并数子”，二次确认后电脑按约定接受。未确认试下不计入；思考中与提子回看、应手演示时先完成当前步骤。
- 用引擎合法停手进入数子：通常追加黑、白两次停手；白棋此前已停时只追加黑棋一次。`agreedPasses` 记录约定追加的停手数，区别于策略选出的停手。
- 数子前保存对局快照，包括棋谱、规则历史、随机状态、重试机会与回看状态。保存前“返回继续下”恢复完整快照，丢弃本次数子中的死子标记与约定停手。自然连续停手也支持返回。
- 玩家停手而电脑实际落子后，显示“电脑选择继续”及提出数子的入口说明。电脑跟停时不出现这条提示。
- 数子界面、复盘与 README 明确：电脑按约定接受结束与用户的死子标记，不自动核验死活；结果依赖标记。保存后旧棋谱不可修改。
- 存档仍使用 v1；新增可选 `agreedPasses` 字段，旧棋谱不变。读取时仍逐手重放，并校验约定标记对应末尾从黑方开始的合法停手。

## 不在本轮范围

自动判断终局、自动跟停、自动标死子、电脑棋力分档、学习记录持久化、方向键操作、`vision.md` 全面整理。空区归属与当前气数不能证明死活，不用它们冒充终局判断。
