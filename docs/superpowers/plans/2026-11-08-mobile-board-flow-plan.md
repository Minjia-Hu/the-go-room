# 手机棋盘操作 — 实施记录

依据：用户确认的移动端方案；延续 B「棋谱编辑部」视觉风格。

## 范围与验收目标

- 375 × 667 CSS 视口、默认字体下，陪练点棋盘试下、读一句理由、确认落子不需要滚动；保留完整九路棋盘。
- 课程首屏同时展示标题、当前任务与完整棋盘。逐步操作、试下确认和计分输入靠近棋盘。
- 短理由直接可见；详细陪练分析可展开。非法落子不能确认，危险演示与正式落子明确区分。
- 操作使用正常文档流，不增加固定底栏；大字号和更矮屏幕允许滚动，不裁切内容。
- 本轮不改首页记录展示、刷新恢复策略、课程标点或结束数子入口层级；不改规则、电脑或学习记录数据。

## 实施内容

1. 新增 BoardLayout，统一任务、棋盘、主要操作和详情四个区域。手机顺序排布，桌面继续左棋盘右讲解。
2. 压缩手机页头与棋盘外围留白，不改变 SVG 棋盘坐标或命中区域。375 像素宽屏中棋盘宽 343 像素。
3. 陪练新增简短说明，优先报告仍然存在的危险，再解释救棋、连接与提子。确认和重新选点放在比较操作之前。提子回看保留简短原因、前后对照与退回重试。
4. 七类课程接入共用布局，把标题与当前任务提到棋盘前。原课程状态与回调继续复用。已记录结果和独立练习题目导航移至课程之后。
5. 切换页面和学习单元时回到顶部，避免从首页下方进入课程后看不到任务。
6. 增加四个简短理由测试；执行全量检查与实际浏览器回归。

## 验收与边界

结果、量测和截图见 [移动端验收](../../qa/mobile-board-flow/README.md)。未进行实体手机验证；真实手指准确度、Safari 地址栏和系统键盘需要用户实测。

## 审查反馈补修

- 补齐七类课程的即时反馈位置。共用 LessonFeedback 保留完整原因；点棋盘后的错误解释首屏可见，页面下方答题时只在必要时将新解释带回视野。
- 手机页眉、图注与小字至少 12 px；图例移至可展开区域，为主要信息留出空间，棋盘宽度不变。
- 共用 ResponsiveExplanation：手机默认折叠、桌面默认展开，监听布局断点并清理监听；保留用户主动展开操作。
- 增加五类真实课程答错回归与一个展开状态测试；浏览器补查全部七类课程，分别记录零滚动和从下方答题返回解释的场景。
